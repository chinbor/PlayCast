# 体积与性能测量

## 方法

Windows x64、Electron 44.4.5，同一台机器进行前后对比。包大小使用实际文件字节数，MB 按 1,000,000 字节计算；不是下载流量、压缩解压后的推算或磁盘占用簇数。原始报告保存在 [performance-data](performance-data/)。

启动计时通过实际 EXE 的 CDP 接口观察：新建隔离资料目录 5 次；复用资料目录时先进行一次不计入的预热，再测 5 次。未清理操作系统文件缓存，不能称为严格磁盘冷启动。DOM ready 不等于首屏绘制或可操作完成；引导页观察包含 CDP 连接和轮询开销，未减去人为估算时间。当前 Electron 未返回 FCP 条目，不能据此报告首屏绘制提升。

交互计时使用真实 Electron 页面与合成登录/房间适配器，测量 10 次标签切换以及 10 条唯一评论从主进程接收到 React DOM 显示。原始界面基线使用已迁移后端，区别在渲染器及窗口加载结构。未连接真实账号、直播间或游戏；不代表平台网络或 GPU 呈现延时。

## 启动与交互对比

| 指标 | 原始中位数 / p95 | 迁移后中位数 / p95 | 每组样本数 |
| --- | --- | --- | --- |
| 新资料启动 → DOM ready | 311.6 / 348.2 ms | 338.2 / 379.3 ms | 5 |
| 新资料启动 → 观察到引导页面 | 356 / 419 ms | 364 / 403 ms | 5 |
| 引导页点击 → 登录页面 DOM | 23.3 / 53.1 ms | 24.3 / 26.8 ms | 5 |
| 复用资料启动 → DOM ready | 302.5 / 318.9 ms | 295.6 / 319.8 ms | 5 |
| 复用资料启动 → 观察到引导页面 | 328 / 388 ms | 327 / 353 ms | 5 |
| 工作台标签切换 → DOM | 5 / 15.1 ms | 4.05 / 15 ms | 10 |
| 合成评论接收 → DOM | 260 / 270 ms | 260.5 / 268 ms | 10 |

新资料启动的 DOM ready 中位数增加 26.6 ms，复用资料中位数减少 6.9 ms；这是小样本的单机观测，不能宣称整体启动明显提速。标签交互保持几毫秒量级，评论仍受原有 250 ms 合并窗口影响。TypeScript 提升契约检查能力，本身不代表运行速度提升。

## 实际包体积

| 内容 | 原始 | 优化后 | 减少 |
| --- | --- | --- | --- |
| NSIS 安装包 | 105.10 MB | 94.37 MB | 10.74 MB（10.2%） |
| 完整运行目录 | 398.47 MB | 338.66 MB | 59.81 MB（15.0%） |
| 应用 ASAR | 13.17 MB | 2.13 MB | 11.04 MB（83.8%） |
| Chromium 语言包 | 50.64 MB | 1.76 MB | 48.88 MB（96.5%） |

主 EXE 仍约 246.09 MB，Electron/Chromium 是剩余体积的主要来源。原 ASAR 中 8.32 MB 的 React/React DOM/scheduler 已编入渲染器，删除了它们的重复运行时副本。

剩余运行目录的主要文件：

| 文件或内容 | 实际大小 | 用途 |
| --- | --- | --- |
| `PlayCast.exe` | 246.09 MB | Electron、Chromium、V8 与 Node 运行时 |
| `dxcompiler.dll` | 25.75 MB | 图形/着色器编译支持 |
| `LICENSES.chromium.html` | 20.47 MB | Chromium 第三方许可与声明 |
| `resources.pak` | 12.44 MB | 浏览器内部资源 |
| `icudtl.dat` | 10.88 MB | 国际化与 Unicode 数据 |
| `resources/app.asar` | 2.13 MB | 应用代码、资源和 ws |
| 其他文件 | 20.91 MB | 图形/媒体库、语言包和快照等 |

进一步优化应区分下载体积与安装后体积。当前安装包已经压缩到 94.37 MB。许可 HTML 的无损 gzip 试算为 2.11 MB，具备约 18.36 MB 的安装后节省潜力，但需提供离线读取方式并核对许可展示要求；本轮保留原始完整声明。图形、媒体和 ICU 文件不能仅凭文件大就删除，必须先证明实际运行不依赖它们，再跨显卡、系统及登录页面验证。

显著降低独立应用体积的方案是迁移到系统 WebView（如 Tauri/WebView2），重写当前 Electron 的窗口、Cookie/session、IPC、加密存储和网络集成。它使用系统共享浏览器运行时，所需运行时占用仍然存在；离线携带 WebView2 或额外 Node 后端时必须计入总成本。这属于架构迁移，需要另行验证功能、登录兼容性和用户资料迁移。

渲染 JS 全部文件合计从 386,053 增至 389,863 字节（约 1.0%）；拆分优化的是各窗口所需的加载图。公共入口约 226.52 kB，工作台入口 116.58 kB、设置入口 7.96 kB、展示入口 3.50 kB，另有按依赖加载的共享块。设置窗的静态依赖不含工作台或挑战/弹幕展示组件。CSS 保持共同加载，约 109.44 kB，以保留原有层叠与布局。

## 优化措施与约束

运行依赖只保留 ws，React 等作为构建依赖；打包保留 en-US、zh-CN、zh-TW 三个 Chromium 语言包。去除五张无运行引用的主题图片，使用明确文件允许列表，并检查源码、开发依赖与用户资料不得进入安装包。Electron/Chromium 和依赖许可证必须保留。

渲染器按工作台、展示与设置窗口动态加载；开发预览仅参与开发构建。保留有界消息数据、窗口化列表、隐藏窗口暂停工作、上下文版本防护和原有 250 ms 状态合并。合成消息延时接近该合并窗口；改动合并频率需要单独的行为和负载验证。

## 验证与环境

2026-10-02，Windows 11 Pro x64、Node 24.18.0 / CI 对照 Node 22.23.3、Electron 44.4.5、TypeScript 5.9.3。干净 `npm ci`、三套严格类型检查、493 项单元测试、生产构建和原生交互回归通过；独立设置、窗口操作、主题、重置恢复、能力限制和开发监听重启均验证。包报告确认无 TS/源码映射/开发依赖，保留三种语言及 Electron、Chromium、项目和 ws 许可证。

标准打包首次下载 Electron 遇网络超时；本次 NSIS 验证使用已经安装的同版本 Electron 目录，通过临时配置的 `electronDist` 完成。打包 EXE 从仓库外运行并使用中文及空格隔离资料目录，验证首次引导、生产权限、资源、正常退出及重启。GitHub 远端流水线尚未实际执行，扫码和真实直播/游戏环境另需验收。Electron 运行时不能通过直接删除必需文件安全瘦身，本轮保留桌面技术栈。
