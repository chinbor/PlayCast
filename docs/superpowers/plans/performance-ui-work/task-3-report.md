## API and lifecycle

- Main workspace mounts only the active page. Unauthenticated users retain onboarding; raw game subscription exists only on the active game-data page and is removed on leave/unmount/scope/auth change. Overlay neither queries main-only data nor subscribes to raw collector data.
- Header/progress/connections use `collector` and current `metrics`; raw responses carry a renderer scope tag so old raw data cannot paint during a scope change.
- `history` requests page 20 summaries and backend metric/result filters; `historyDetail` is requested/mounted only when expanded. Null/unreadable detail renders an explicit unavailable alert, and closing/reopening retries. Archived timestamps/rules/contribution semantics remain in the dedicated detail renderer.
- `gifts` requests merged catalog items keyed by scope/version/loading and only for visible configuration/rules. Existing rule editors receive this query result as a local view-model catalog, not a full snapshot dependency.
- `feed` uses generation/after cursors, honors reset and caps retained rows at 500. Search/filter sees all retained rows; frozen views remain bounded. Only the viewport plus overscan mounts. Message buttons open a wrapping full-content dialog, preserving long comments. Clear remains the backend `clearFeed` action.
- `challengeLog` follows `logsVersion` and scope. Current feedback stays in progress with local expand/collapse; it does not route to an unrelated historical record.
- `diagnostics` mounts only inside expanded advanced options and follows safe aggregate counters. UI renders only returned method/stage/code/timestamp/size. Unsupported, decode, frame, processing and gift counters are distinct.
- `storage` sizes query on mount/manual refresh/cache-clear success, never on each message revision. Pending/error uses lightweight live `s.storage`. Clear caches has a separate explanation/confirmation and no history purge.
- Shared Select supports arrows, Home/End, Enter/Space, Escape, Tab, type-ahead, outside dismissal, disabled/error states, selected announcement and scroll/resize positioning. Portals attach to the closest dialog when applicable, preserving native dialog ownership; current production history filters are outside a modal. Escape/selection restore trigger focus; Tab does not.
- Account management from connections closes settings before opening the existing AccountPanel.

## Independent rerun timeout diagnosis

The root review reran unit tests/build successfully, but one guided run reached the global 60-second watchdog without a local failure. Capture timestamps narrowed the stall: `01-platform.png` through `07-progress.png` were updated at 18:05:04–18:05:16; `07a-rules-edit.png` and all later images still had the preceding successful run's 17:58/17:59 times. Immediately after capture 07, guided smoke awaited `did-finish-load` around `webContents.reload()` with no timeout. The subsequent DOM waits are already locally bounded. This evidence localizes the missing diagnostic boundary to reload; it does not establish the underlying intermittent Chromium/load-event cause.

With root authorization, only `tests/guided-smoke.cjs` changed: its one-line unbounded reload promise became a promise with start/completion logs and an 8-second timeout. Timeout removes its listener and rejects with only `isLoading`, page title and local URL. Successful load clears the timer. Reload and all original restored-progress/rules assertions remain mandatory; no assertion was skipped and no production file changed.

Exact replacement at the former line 77:

```js
console.log('Guided smoke: renderer reload starting')
await new Promise((resolve,reject)=>{
  const contents=main.webContents
  const finished=()=>{clearTimeout(timeout);console.log('Guided smoke: renderer reload completed');resolve()}
  const timeout=setTimeout(()=>{contents.removeListener('did-finish-load',finished);reject(Error('Renderer reload exceeded 8 seconds: '+JSON.stringify({isLoading:contents.isLoading(),title:contents.getTitle(),url:contents.getURL()})))},8000)
  contents.once('did-finish-load',finished)
  contents.reload()
})
```

One authorized rerun used the same guided command/output directory above. Both reload messages appeared, then guided + performance smoke passed with exit 0 (session 22818). The transient stall did not reproduce. This is a test diagnosability improvement, not a claimed product fix or proof that the environmental reload stall can never recur. The two independent-review Minor observations (account-wide completed count next to filtered history total; End with a disabled last Select option) remain unchanged for root triage.
