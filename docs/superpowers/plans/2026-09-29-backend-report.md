## Behavior

- Rule validation defaults comments off, trims/deduplicates at most 20 nonempty keywords of at most 80 characters, and rejects an enabled empty list transactionally. Matching is case-sensitive literal substring matching. A distinct matching comment gives exactly one target point while running; duplicate delivery is ignored, while separate messages by the same user count. Applied like/follow/comment/gift rewards accumulate in `contributions`, respecting the target cap. Older v1/v2 saves have `contributionsComplete: false`; fresh sessions use `true`. Session timestamps are recorded, with unknown legacy creation time left `null`.
- `challenge-library.cjs` stores one draft per platform/account/room/metric, returns cloned drafts, exposes current-scope slot summaries, and archives cloned full settlement records by ID. History is selected by authenticated platform/account across rooms, sorted newest first, without truncation. A settled record is idempotent and independent of later engine state mutation.
- Product actions `chooseGameplay`, `resumeChallenge(metricId)`, `configureChallenge`, `finish`, and `end` follow the renderer interface. Switching platform, room, account, metric, or source parks the current draft. Resume returns paused and the engine re-establishes a game baseline; no offline game growth is added. `finish` below target is rejected. `end` archives as completed if already at target, otherwise ended-early. The engine ignores later game polls/events for ended sessions. All live challenge mutations require authenticated matching binding; an auth-checking state pauses running live sessions and blocks game polls. Unauthenticated snapshots hide slots/history and the prior account's active details. History remains visible for an authenticated account before room confirmation.
- Demo uses its own in-memory library and binding, including simulated comments/gifts and gameplay selection. Demo drafts/history are omitted from the live save.
- Accepted business mutations flush immediately to the compatible `challenge-v1.json` path. Saves write a temporary file, atomically rename it, and update an atomic backup. Primary corruption recovers from the backup and the damaged primary is copied to a `.corrupt-<timestamp>` file before replacement. Invalid or unknown primary/backup structures remain untouched and set `persistenceError`. Write failures are visible in that field. Normalizer state, drafts, history, presets, catalog, and current challenge are saved together.
