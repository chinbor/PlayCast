# 功能归属式设置与分类弹幕缓存

日期：2026-09-30

状态：用户已确认规格，并补充“注意缓存，不要膨胀”。实施前须落实下列跨层资源约束。

## 1. 目标与范围

让用户在当前功能内完成操作与设置，减少进入全局设置后跨功能寻找选项的负担。同时解决累计互动统计仍有数字、分类消息却被高频消息挤空的问题。

本轮包括导航调整、设置归属、统一展示窗口入口、分类缓存及统计文案。不更换品牌视觉、不新建直播平台、不改变挑战算法、不实现游戏数据展示窗、不增加弹幕长期存盘功能。

保持现有登录流程与认证边界，不在本轮额外改造扫码、自动恢复页面或自动开始挑战的策略。登录且确认房间后，弹幕查看与弹幕展示不依赖创建挑战。

## 2. 已确认的信息结构

一级导航仅三个页面，名称固定：

| 一级页面 | 二级内容 | 所属展示窗口 |
| --- | --- | --- |
| 当前挑战 | 当前挑战、挑战历史 | 挑战展示窗 |
| 弹幕消息 | 分类统计、搜索、消息列表 | 弹幕展示窗 |
| 游戏数据 | 当前对局和游戏指标 | 本轮不新增窗口；后续按相同方式扩展 |

不设置独立“直播展示”页面。挑战历史从一级导航迁到当前挑战内部，保留现有筛选、详情与手动删除能力，不自动删除历史。

切换二级历史页只改变浏览位置，不切换活动挑战、不改变展示窗数据。完成或提前结束挑战后，进入“当前挑战 → 挑战历史”。从历史返回当前挑战不修改存档。切换玩法、继续草稿、快捷键校正等现有跳转统一定位到“当前挑战 → 当前挑战”。

历史页面不提供把旧挑战直接投放为当前展示的操作。当前挑战的展示入口始终针对当前活动挑战，无活动挑战时遵循原有可见性与打开权限，不伪装成历史回放。

## 3. 设置归属

### 3.1 当前挑战

互动规则在当前挑战内编辑，不再打开带连接、存储等分类的全局设置。默认显示规则摘要，点击“编辑规则”打开只含规则的编辑面板，明确新规则仅影响之后的互动。

玩法切换、目标与进度校正、开始／暂停／结算保持现有业务行为。校正入口留在挑战页，不搬进连接管理；游戏起点重新校准保留风险确认。

### 3.2 弹幕消息

搜索与分类筛选直接位于消息页。默认突出消息内容和当前筛选，显示用户 ID 等低频选项进入“显示选项”。清空记录、扩展消息与诊断入口收进“更多”，不在正常消息流前展开大量说明。

暂停显示不暂停采集或挑战计数。用户翻看旧消息时保持可见位置；新消息提示和“回到最新”沿用稳定滚动行为。

### 3.3 展示窗口入口

当前挑战和弹幕消息页右上角各使用同一种“展示窗口”控件，只控制本功能的窗口。

- 未打开时突出“打开展示窗”。
- 已打开时显示开启／锁定状态，并提供“窗口设置”。
- 展开操作包括外观设置、锁定／解锁、关闭；避免默认横排一长串按钮。
- 外观设置只展示该窗口的配置。主题、透明度为常用项；尺寸、置顶和挑战纯净模式等低频项折叠。
- 挑战保留四套地区主题、真实礼物图标和庆祝预览；弹幕保留深浅主题、纯色功能图标、在线显示和类别可见性选项。
- 主页面和弹窗内共享同一套外观字段组件及校验，使用同一份已保存配置；主页面可另含只适合主窗口操作的高级尺寸项。
- 未保存的修改只在当前编辑面板预览；保存成功才更新已保存配置并同步其他窗口。取消还原；带修改离开时提示保存、放弃或继续编辑。
- 保存失败保留草稿并显示可重试错误；不可显示成功提示。
- 接收到其他入口的设置更新时，无修改草稿跟随更新；有修改草稿不静默覆盖，提示配置已更新，允许重新载入或明确保存本次编辑。

窗口关闭、锁定、移动不影响直播连接或挑战。保留系统级穿透、固定右上角解锁热区及主页面解锁后备入口。主页面切换标签不关闭已打开窗口。

游戏数据本轮只保留扩展接口位置，不展示不可用按钮或“敬请期待”卡片。后续增加窗口时复用入口和生命周期，不更改一级导航。

### 3.4 公共连接与全局设置

账号资料和退出登录统一由个人空间管理。顶部直播、游戏状态提供对应的局部连接面板：直播连接面板只管理账号摘要、房间和连接；游戏面板只展示连接信息与相关操作。

全局设置保留快捷键、本地存储与折叠的高级诊断，不再包含互动规则及两种展示窗口设置。

Cookie 手动导入、详细解码计数、未适配类型、正式／演练切换放在高级诊断，不删除现有能力。正常连接面板优先展示明确状态、失败原因和可采取的操作，详细协议数据默认收起。

从消息页“管理直播间”和顶部直播状态进入同一个连接面板；避免重复维护两套房间草稿与连接逻辑。打开个人空间前关闭连接面板，避免模态窗口层层叠加。

## 4. 分类缓存与统计口径

### 4.1 已确认根因

现有 `electron/message-feed.cjs` 把所有类型放入同一个最多 500 条的队列；累计 counts 不随记录淘汰减少。`MessagePanel` 再对这 500 条做分类筛选。

独立合成复现：1 条礼物消息（5 件）、1 条关注后加入 500 条进场。最终累计礼物 5、关注 1，但对应保留消息均为 0。这是共享队列淘汰和统计口径差异，不是礼物解析失败。

### 4.2 新保留策略

评论、点赞、进场、关注、礼物各保留最近 200 条有效消息，总条数最多 1,000。某类的新消息只淘汰该类的旧消息，不挤占其他类别。

每类另外设置 1 MiB 的序列化显示记录字节预算，合计最多 5 MiB；超过预算时淘汰该类最旧记录，所以“200 条”是上限而非最低保证。该预算不等于 Electron 总内存上限，需同时控制去重表、组件节点和读取中的快照数量。

缓存仅存显示与消息详情所需的白名单字段；保留现有文字长度约束，不保存任意原始协议对象、Cookie、头像二进制或图片内容。礼物使用安全的图片 URL，网络加载失败保留文字及占位图。现有礼物连击增量、去重语义和挑战消费链路不变，不因展示缓存调整重复奖励。

“全部”按全局接收序号合并当前各分类保留的消息，因此是“当前保留记录”，不是完整且连续的历史。不得用“完整历史”或“最近连续 1,000 条”描述它。

清空记录清除全部分类缓存，并变更缓存代次；累计统计与挑战不变。不会新增重置累计统计的按钮。账号、房间、来源切换和退出登录继续按原有权限范围隔离，立即清理旧界面，拒绝旧异步结果。

### 4.3 读取与渲染

主进程仍是唯一采集入口和消息缓存权威来源。主界面与弹幕窗使用一致的分类、保留上限和游标语义，不各建一个采集连接。

保留增量读取。响应必须携带缓存代次、累计统计、各类保留数量与淘汰同步信息，使读取端能同时追加新记录并移除服务端已淘汰的记录。游标失效时返回有界重置快照，不假定全局序号连续就代表所有分类历史仍存在。

页面与弹窗复用合并、过滤、淘汰及请求调度逻辑。每个读取端最多一个请求在途，合并重复刷新；隐藏或未挂载页面不持续读消息，恢复后补齐当前缓存。不能通过每次刷新替换为加载页实现同步。

继续使用固定高度虚拟列表和有限预渲染。切换分类或搜索时钳制滚动位置；有新消息时保留阅读锚点，锚点确被淘汰则明确提示并定位到最近可用位置。显示选项只影响对应视图，不改变采集、保留或挑战计数。

### 4.4 文案

顶部明确标注“本次采集累计”，统计不随筛选或缓存淘汰变化。点赞和礼物使用数量单位；评论、进场、关注按现有事件口径说明，不声称是去重人数。在线仍是平台瞬时统计，缺失显示“—”，不参与分类筛选。

分类列表另显示记录数，例如“累计收到 128 个礼物 · 当前保留 36 条礼物消息”。搜索时显示“匹配 8 条／本类保留 36 条”。

空状态依据可用事实区分尚未收到、当前搜索无匹配、记录已清空；达到保留上限或发生淘汰时提示“仅展示当前保留记录”。累计统计不能还原已删除的消息内容，不承诺补回升级前已经淘汰的记录。

## 5. 组件边界与兼容

### 5.1 用户补充：缓存不可无界增长

- 条数和字节预算必须同时覆盖采集缓存、主界面副本和弹幕窗副本。单个视图不得额外维护无限历史、更新队列或分页快照；暂停阅读最多保留一个有界快照，恢复、离开或范围切换后释放。
- 每个 live／test 消息源分别受上述预算约束，不为每次房间切换创建永久保留的缓存。未认证消息源始终为空。
- 消息去重 Set 与连击 Map 各最多 20,000 项；外部标识先验证长度再生成固定长度键，不让超长 ID 绕过“条数上限”。无效输入不得占用去重容量。保留现有去重与连击增量语义，不借本轮改动自动重复计数。
- 待处理请求和调度标记有界；组件卸载时解除监听、计时器与观察器，丢弃旧请求结果，不重试堆积。
- 应用 UI 使用独立、非持久化且关闭 HTTP 缓存的 session，主窗与展示窗共用它。平台认证 session 保持隔离，不借清缓存操作清 Cookie、登录凭据或网站存储。图片只保存 URL、不保存 base64 副本，不新建礼物图片下载目录；浏览器解码内存仍须通过虚拟列表与窗口关闭释放来检查。
- 既有礼物目录缓存继续保持 16 MiB 序列化预算，增加作用域数量上限 8；所有增加作用域的路径（包括读取空作用域和失败记录）都执行淘汰。名称、图标 URL 和作用域键长度受限，合并展示字段不重复写入磁盘。
- 挑战存档、用户手动保留的历史和加密凭据是持久数据，不是可以自动淘汰的缓存；不以控制缓存为由自动删除它们。
- 验收需包含至少 100,000 条长文本合成消息、重复清空／切换范围、反复开关窗口后的记录数、字节数、去重项及监听清理检查。Electron 总内存含运行时和图像解码，不能承诺总内存等于 5 MiB，也不能只凭消息条数判断无泄漏。

### 5.2 模块划分

- 主导航负责一级页面与挑战二级页，不承担业务状态修改。
- 功能设置面板各自拥有草稿和保存状态；公共保存提示、未保存离开确认与窗口入口组件复用。
- 窗口管理继续使用现有 challenge/messages 身份及窄 IPC 白名单。扩展通过显式登记窗口能力，不增加任意窗口或任意路由执行能力。
- 消息缓存模块负责分类保留、统计、游标与重置；共享读取模型负责请求合并和本地缓存同步；页面只负责展示。
- 现有主题、透明度、尺寸、窗口状态权限、挑战存档、历史及登录凭据保持兼容；无须用户重新配置已有主题。
- 不迁移弹幕正文到磁盘。现有本地挑战记录只因正常业务操作改变，不因导航迁移而重建或清零。

## 6. 验收

1. 一级导航只有当前挑战、弹幕消息、游戏数据；历史仅在挑战二级，结算、切换玩法、快捷键路由正确。
2. 无活动挑战也可使用直播消息和弹幕窗；查看历史不改变活动挑战或直播展示。
3. 两页的展示入口只操作自身窗口，主页面／弹窗保存同步，预览取消不改已保存值，失败及未保存离开都有明确反馈。
4. 开关某窗口、切换页签、隐藏分类均不改变挑战计数、账号或平台连接数量。
5. 礼物和关注之后灌入至少 5,000 条进场／点赞，礼物和关注记录仍可筛选；每类不超过 200，总记录不超过 1,000，字节预算有效。
6. 覆盖某类数量淘汰、字节淘汰、稀疏序号、过期游标、分类切换、搜索、清空、断线恢复与旧请求返回，不保留服务端已淘汰记录。
7. 以不均匀分类分布测试实际渲染类型，而非仅验证分类按钮或相同条数；礼物数量与消息条数明确区分。
8. 虚拟列表节点有界、刷新不闪空、阅读锚点稳定；隐藏暂停与恢复读取均在实际 Electron 中验收。
9. 账号／房间／来源切换、退出登录后立即清除旧内容；历史、存档和登录凭据不被测试改动。
10. 长标题、大数值、多礼物规则及小窗口可读；物理穿透、多 DPI、直播软件采集未实际执行时继续明确列为手动验收项。
