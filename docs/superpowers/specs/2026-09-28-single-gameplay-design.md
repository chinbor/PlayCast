# 单玩法直播互动工具：产品与技术设计

日期：2026-09-28。状态：用户已批准开始实施，追加个人空间与退出登录；本文不是已实现功能清单。

## 1. 目标与范围

将当前偏调试面板的应用收敛为「选择平台 → 扫码登录 → 确认直播间 → 选择玩法及规则 → 开始互动」。沿用 Electron、React、UnoCSS、Vite，开发端口保持 5188。

首版只支持抖音，同时只运行一个挑战。用户明确要求为后续直播平台保留扩展性：本次建立统一平台适配边界，但只实现抖音适配器，不预做其他平台。当前不做多挑战面板、规则编排器、转发服务或独立采集服务器。请求与消息解析在本项目实现，dycast 和 DouyinLiveWebFetcher 仅作为参考。不在本次加入 Windows 安装包发布流程。

观众互动增加目标数，游戏进度增加完成数；二者不能混为一个计数。保留手动校正、快捷键、跨对局累计和独立展示窗口。

## 2. 用户路径与页面

### 首次使用

1. 平台页只展示「抖音直播」入口，不展示不可用平台占位。
2. 登录页打开独立的抖音官方页面，由用户扫码完成认证。首版不自行生成或伪造二维码。提示「在官方窗口选择扫码登录，完成后返回」。登录窗口不因采集连接、重试或断开而自动关闭。
3. 验证登录后让用户填写并确认直播间，保存最近一次选择；不默认登录账号就是目标主播。重新进入时可以修改房间。
4. 选择一个玩法，设置初始目标和互动规则，点击开始。

再次启动时恢复平台和最近房间，验证已保存登录状态；有效则跳过登录步骤。已有未结束挑战以暂停状态恢复，需要用户继续。凭据失效时保留挑战进度并引导重新登录；网络失败显示「暂时无法验证」，不能误判为账号退出。

### 主界面

- 「玩法进度」：当前玩法、已完成 / 当前目标、剩余数、游戏与直播连接状态；暂停、继续、结束和手动校正。规则摘要可展开编辑。
- 「弹幕消息」：独立展示评论、点赞、关注、礼物和进入直播间消息。消息展示与挑战是否运行分离。
- 设置内收纳账号管理、诊断、高级 Cookie 导入和原始游戏数据。普通动线不要求用户接触 Cookie。
- 顶栏提供「个人空间」：展示已认证平台返回的头像、昵称、公开账号标识、个性签名、粉丝数和关注数；缺失字段显示未提供，不推断为 0。支持刷新资料和退出登录。退出需确认，暂停当前挑战、断开采集、清除本应用该平台认证存储与内存资料并返回登录步骤；挑战历史保留。同一账号重新登录可继续，换账号需结束旧挑战。
- 使用现有明亮、轻松的视觉方向。桌面固定外框，内容区独立滚动；弹幕页只有列表滚动。极小窗口回退为单页面滚动，不再出现嵌套双滚动。

## 3. 五种玩法及统计口径

用户选择 A 口径：人头按主播个人，野区目标按主播所在队伍。

| 标识 | 名称 | 完成数来源与范围 |
| --- | --- | --- |
| champion-kills | 人头击杀 | 当前玩家的累计英雄击杀数 |
| creep-score | 补刀 | 当前玩家接口提供的 creepScore 增量 |
| baron-kills | 大龙击杀 | 主播所在队伍的大龙击杀事件 |
| dragon-kills | 小龙击杀 | 主播所在队伍的小龙击杀事件，首版包含接口归为 DragonKill 的各龙类型，包括远古龙 |
| herald-kills | 峡谷先锋击杀 | 主播所在队伍的先锋击杀事件；不计召唤先锋、虚空巢虫等其他事件 |

补刀的接口口径必须与实机计分板核对。未验证野怪是否包含前，名称使用「补刀（接口口径）」并说明边界，不能宣称是纯小兵击杀数。

现有代码只实现个人英雄击杀。BaronKill、DragonKill、HeraldKill 是待核对的事件适配目标，不代表当前补丁已实测。实现时验证事件名、字段、玩家标识和队伍归属；不能识别归属的事件不自动计数，并给出可手动校正的提示。

能力状态区分「等待对局」「可用」「当前模式不适用」「未验证 / 暂不可用」。未发生过某类击杀、事件列表为空，不代表接口不支持该玩法。未通过协议验证的适配不能显示为已可用。五张玩法卡展示这些状态。

## 4. 规则

每个玩法保存自己的上次配置；只有当前挑战消费消息。每类规则可以关闭，数值必须为有界整数。

- 初始目标：大于等于 0。
- 点赞：每 N 个赞，目标 +1；N 为至少 1 的整数。余额跨消息保留。首版不额外暴露点赞奖励倍数。
- 关注：每个新增关注，目标 +M。沿用同一挑战内同一用户仅奖励一次，避免反复取关重关刷目标。
- 礼物：可添加多行「选择礼物 → 每个增加 M」。按稳定礼物 ID 匹配，而不是仅凭名称；同一礼物不能重复配置两行。
- 评论继续展示，但新挑战默认不启用评论关键词加目标功能。

规则调整只影响之后收到的消息，不追溯已计数数据。调整点赞阈值时重新开始积攒点赞余额，保存前明确提示。达到目标仅显示达成状态，不自动结束挑战；后续互动仍可增加目标。

### 礼物连击：每个实际礼物都计入

只有明确为累计式连击的协议消息才计算差额；独立赠送按单笔实际数量计入。不能按「用户 + 礼物」永久去重。

累计通知 1 → 2 → 3 → 结束通知 3，对应新增 1、1、1、0，总计 3 个。每个奖励 5 时目标共增加 15。同一用户下一轮赠送仍全部计数。

连击状态按房间会话、用户、礼物 ID、连击组标识隔离，高水位不因重复、乱序、结束包下降。消息 ID 过滤重复投递，但同一连击的累计数量增长不能被误过滤。缺少必要组标识时不猜测数量，记录未能安全计入的原因。

暂停时继续更新消息去重和连击高水位，但不增加目标；继续后仅计新增部分。连接重试不得丢失当前挑战的高水位，也不能把已经计过的礼物再算一遍。

## 5. 礼物目录与真实图标

下拉选择器支持按名称搜索，显示图标、名称和价格（接口提供时），支持多个不同礼物规则。

目录优先读取当前登录会话及直播间实际可用的礼物数据，规范化为平台 ID、礼物 ID、名称、图标 URL、价格及平台币种（可空）、来源、更新时间，按平台、账号及房间隔离缓存。目录请求在主进程执行，凭据只发送给核验过的官方来源；不能将 Cookie 随图标请求发送到第三方图片服务。

参考项目已证实礼物消息包含 ID、名称、价格及 image URL；尚未验证完整目录获取。实现先确认实际目录请求及响应，再集成，不虚构接口地址或静态「全部礼物列表」。礼物消息可补充已知礼物，但必须区分「当前目录」「缓存」「已收到的礼物」，不能把观察到的子集标为全部。

目录加载失败时允许重试，展示缓存时间和范围；无缓存则明确为空。已有规则不因暂时加载失败被删除。图标使用真实素材，失败时显示中性占位和礼物名称，不用生成图或表情冒充官方图标。若完整目录技术路径无法验证，报告限制，不将这一需求标记为完成。

## 6. 登录保存与安全

沿用独立 Electron Douyin session，官网窗口、采集引导页、HTTP 请求和 WebSocket 使用同一账号会话。Cookie 存在、账号认证有效、礼物已实际收到是三个不同状态。

使用经过验证的官方账号请求判断登录有效性。将登录所需的限定域 Cookie 及必要属性在主进程加密持久化，使用 Electron safeStorage 的系统保护能力，保存于应用用户数据目录。启动恢复时保留域、路径、有效期和安全属性，不人为延长服务端会话有效期。加密能力不可用时禁止明文降级，告知本次登录不能安全持久保存。

原始凭据不得进入 React 状态、广播快照、挑战 JSON、日志、截图或测试输出。退出账号清理本应用的会话和加密凭据，不清理用户其他浏览器账号。登录窗口保持独立，只有用户关闭、明确退出账号或应用退出才关闭。

## 7. 计数生命周期与架构

### 平台适配合同

平台扩展与游戏玩法扩展是两个独立方向。注册表首版只注册 DouyinAdapter；添加新平台是在同一合同下新增适配器及必要的登录 UI，不修改挑战算法或在通用组件中堆叠平台判断。暂不实现动态插件安装、热加载或跨平台同时采集。

适配器提供以下职责明确的接口，具体命名在实施计划确定：

| 接口组 | 合同 |
| --- | --- |
| 平台描述与能力 | 稳定 platformId、名称、展示图标、支持的登录方式、消息类型、礼物目录能力及计数限制 |
| 身份认证 | 发起 / 取消认证、查询 / 验证状态、恢复凭据、退出；可支持官方窗口扫码、授权跳转或其他平台要求的方法，不强迫每个平台使用 Cookie |
| 房间解析 | 将用户填写的房间号或受支持链接解析为规范房间标识与展示信息，明确校验失败原因 |
| 采集生命周期 | 连接、断开、订阅统一消息及状态、释放资源；重试、心跳、ACK、签名在适配器内部处理 |
| 礼物目录 | 获取 / 刷新礼物、说明目录是完整列表还是观察子集、提供缓存范围和来源；不支持目录的平台可明确返回不可用 |

身份状态统一为未登录、认证中、已验证、失效、验证暂不可用等语义。原始 Cookie、token、refresh token 的格式和有效性判断由平台负责，通用界面不读取秘密。加密存储服务提供底层保护，存储命名空间按平台及账号划分；退出某平台不得清除其他平台凭据。抖音独立 session 保留，后续平台使用各自独立分区。

通用引导展示注册平台及其能力；认证步骤允许适配器提供受限的展示信息和专用组件。通用流程不假设所有平台一定提供二维码、关注事件、点赞增量或可枚举礼物。某能力缺失时不展示对应可配置规则，明确说明不可用，不用其他事件冒充。

### 统一互动消息

统一消息包含 platformId、accountScope、roomId、连接代次标识、原始事件标识、事件类型、发生 / 接收时间、平台内用户标识及展示信息；礼物额外包含平台内 giftId、名称、图标和实际新增数量。事件类型先限定 like、follow、comment、gift、enter，不因新平台接入扩展成任意脚本规则。

适配器负责理解原始消息是增量还是累计量，将其转为统一增量事件。累计连击高水位由可复用的规范化模块维护，抖音适配器配置自己的连击键与结束语义；挑战引擎不读取抖音协议字段。规范化模块允许保存 / 恢复去重和连击高水位，避免重连或应用恢复后重复奖励。

区分连接代次与事件身份：连接代次用于丢弃旧连接迟到回调，不能用于制造新的事件 ID 以绕过重连去重。同一原始累计包的数值增长由规范化模块处理，输出唯一的增量事件；重复投递不能再次产出奖励。平台没有可靠事件身份或数量时显式标记计数不可靠，不编造 ID 来宣称精确计数。

用户、礼物和消息标识都必须携带平台及必要的账号 / 房间命名空间。同一个 giftId 在两个平台不是同一种礼物，平台币种也不混算。规则用 platformId + giftId 定位礼物；关注去重使用平台内用户身份并绑定当前挑战。

当前挑战绑定 platformId、账号范围和 roomId。切换账号、平台或房间必须先结束当前挑战并断开旧采集；新挑战建立独立规则与计数状态。接入非当前绑定来源的事件一律不计数。点赞余额、去重集合、礼物缓存及规则不能跨来源串用。

### 模块边界

- 平台注册与合同：提供可用平台、能力和适配器生命周期；当前仅抖音。
- 加密凭据存储：提供平台隔离的安全持久化，不解释平台认证协议。
- DouyinAdapter（复用 douyin-session / douyin / douyin-wire）：实现官方登录、验证、房间解析、协议连接及抖音目录获取，对外输出统一状态与互动增量消息。
- 礼物目录服务：统一目录模型、缓存与平台来源隔离；具体请求委托适配器，不负责挑战奖励。
- 消息规范化模块：基于平台给出的事件语义处理累计连击和重复投递，保留可恢复状态。
- 游戏指标适配层：把本地游戏快照转换为选定指标累计值及能力状态；负责队伍归属与事件去重。
- challenge：一个当前挑战，接收规则、游戏指标和互动消息，维护目标、自动完成数、校正及暂停状态。
- product：通过注册表组合当前平台、目录、游戏与挑战，对界面提供最小必要状态和受校验动作，不直接解析平台协议。
- React：引导流程、玩法选择及规则表单、进度和弹幕；不持有凭据、不自行推算权威计数。

预留 metricId 和规则模型扩展点，但不新增并行挑战调度器。归一化消息只进入当前挑战一次，原始平台协议不进入通用计数引擎。

### 生命周期

开始或首次获得有效游戏快照时建立基线，不计入此前发生的击杀与补刀。暂停期间持续跟踪游戏基线，继续时不补记暂停期间发生的进度。无游戏连接时允许先开互动，界面清楚显示等待对局。

同一挑战跨局累加，新对局清理上一局事件去重集合及基线；短断线尽量依据同局累计值补齐。沿用超过两分钟中断时暂停并重新校准的安全策略。游戏时间回退、身份变化或异常计数下降需区分新局与异常，不能产生负增量或重复奖励。

保留永久修改完成数及临时补记。临时补记只在对应指标的真实增量到来后抵消，接口追平不能再次增加完成数；跨局或指标变化不能误抵消别的玩法。切换玩法必须结束当前挑战，新建独立挑战。

挑战数据使用版本化模型迁移。旧人头挑战保留进度并暂停恢复；旧名称匹配礼物规则需要用户确认 ID 映射，未确认时关闭该行并显示提示，不能悄悄匹配到另一礼物。旧评论计数停用且告知用户。新建挑战使用新的简化规则表单。

## 8. 验证与验收

1. 纯逻辑测试覆盖五种指标、个人 / 队伍归属、敌队排除、未知归属、空事件、重复及乱序事件、新局、暂停继续、延迟补记、数据中断及迁移。
2. 礼物测试覆盖独立多次赠送、累计连击 1/2/3/3、同一用户下一轮、不同用户同款、重复包、乱序包、暂停跨连击、重连高水位。示例最终必须是 3 个礼物、目标 +15。
3. 登录测试使用隔离账号存储和假凭据验证加密持久化、重启恢复、失效 / 网络失败区分、注销清除及快照不泄密。真实扫码由用户本人完成。
4. 目录测试覆盖 ID、真实图标字段解析、搜索、多条配置、重复配置拒绝、缓存与空态、图标加载失败，目录失败不删除规则。
5. UI 冒烟覆盖首次引导、再次进入、玩法选择、开始暂停结束、规则编辑、快捷键、弹幕与独立展示窗口；在常规桌面、小窗口和窄屏验证无横向溢出及嵌套双滚动。
6. 在现有单元测试、构建和 Electron 冒烟通过后，仍分别注明真实扫码、跨重启登录、实时礼物及五种真实游戏事件是否经过实机验证。模拟测试不能作为真实接入成功的证明。
7. 使用仅用于测试的第二平台适配器验证合同：无需修改挑战算法即可消费统一消息；不支持点赞或礼物目录时 UI 正确降级；不同平台相同用户 / 礼物 / 消息 ID 不串数据；注销与清理只作用于当前平台；断开的旧连接不能继续增加计数。测试适配器不作为真实平台出现在产品入口。

## 9. 实施顺序与交付边界

先验证目录及游戏事件协议，定义并测试平台合同，再将现有抖音实现收拢到适配边界、完善安全会话保存与游戏指标适配、扩展挑战规则，最后串联简化 UI 并回归。保留现有采集、消息面板和校正机制，不修改参考仓库。
