# 性能、存储、连接管理与共用组件调整

日期：2026-09-29

状态：完整书面设计已获用户确认（“好的哈”），2026-09-29 开始按实施计划执行。

## 目标与范围

降低高频直播消息和游戏数据刷新引起的主进程阻塞、跨进程复制和隐藏页面渲染成本；保留现有挑战计数、连击增量、跨账号隔离和断点恢复语义。此次不是全面重做视觉品牌，也不增加新直播平台。

用户要求：游戏数据独立主 Tab；移除设置中的变化记录；连接管理分组明确；限制可再生本地缓存；排查解码错误；统一下拉框等功能组件。

## 已有证据与限制

- 弹幕展示最多 500 条，不是无限历史；挑战存档不包含弹幕展示列表。
- `product.cjs` 的 `changed()` 默认每次同步序列化全部存档，并多次复制备份；消息接收和连接状态更新均可能触发。
- 游戏采集约每 200 ms 推送完整数据；产品广播包含完整历史、礼物目录和消息列表，隐藏页面仍参与渲染。
- 实际存档采样约 1.2 MB，仅一条历史；礼物缓存、消息去重状态占主要部分。以上不能证明整机卡顿由内存溢出导致。
- `douyin-wire.cjs` 在分派消息类型之前读取用户嵌套字段。参考协议的 `ControlMessage.status` 是字段 2 的整数，不是用户对象。使用合法字段构造的控制消息可稳定触发 `Buffer.from(bigint)` 异常。未知类型也可能被错误解码后才进入 default 分支。
- 连接器把解码与后续回调放在同一个 catch 中，处理异常可能被统计为解码错误。未记录原始失败类型，无法追溯截图中的全部 301 次错误。
- 历史筛选使用原生 select，展开菜单采用操作系统样式；不是单纯边框颜色问题。

## 选定方案与替代方案

采用采集、持久化、展示解耦的定向调整。仅降低弹幕条数不能解决同步存盘和完整广播；全面更换框架或引入数据库会扩大迁移风险，本次不采用。

### 一、后台计数与界面刷新

- 保留当前游戏采集节奏和所有直播互动的规则计算，不以丢弃礼物或点赞消息换性能。
- 高频状态广播合并至约 250 ms 一次；用户操作及时反馈，计数引擎不依赖当前页是否可见。
- 常规广播仅带当前挑战展示字段、连接状态和版本标识，不附带去重集合、全部历史或完整礼物缓存。
- 弹幕仍保留最近 500 条；以序号获取增量，发生序号缺口时重新加载有界窗口。列表只挂载可见行，暂停展示不暂停后台计数。
- 隐藏 Tab 不挂载昂贵内容；游戏数据仅在该 Tab 激活时订阅，展示刷新最多每秒两次。原始 JSON 按需生成并可暂停查看。
- 历史每页 20 条摘要，展开记录后单独读取详情；礼物目录按需请求，更新时通知版本，不重复推送目录。
- 最小化和悬浮窗场景继续计数；悬浮窗只订阅目标与进度等必要字段。

### 二、本地存储与安全边界

- 拆分运行中挑战、不可变历史、可再生礼物缓存和恢复日志；不再每条消息重写所有历史与缓存。
- 增量记录与检查点使用有序写入和原子替换。后台整理检查点，避免主进程同步复制大文件；退出、退出登录、切换账号前等待必要写入完成。
- 恢复日志把计数变化与对应去重/连击高水位作为同一恢复单元，避免恢复后重复奖励。已确认持久化与尚在写入中的状态明确区分，失败可见，不宣称断电绝对零丢失。
- 历史详情独立保存，索引分页读取。未完成挑战和所有完成历史不自动删除；因此重要用户数据仍随使用增长，容量上限仅约束可再生缓存。
- 礼物缓存仅保存可重建所需数据，去掉重复合并数组；缓存总预算 16 MiB，按最近使用淘汰；不删除规则中已选礼物的 ID、名称、图标或奖励配置。
- 诊断记录仅保留最近 50 项类型、阶段、错误代码、时间及字节数；不保存原始消息、用户名称、Cookie、带凭据的网址或任意异常全文。
- 消息去重状态保持现有 20,000 项边界；紧凑身份摘要与旧格式兼容迁移，保留作用域和连击高水位。不得为了减小文件移除有效防重语义。
- 设置增加本地存储页：分别展示挑战/历史、缓存和恢复文件占用；清理按钮仅处理应用自行管理的礼物缓存和诊断记录，明确不会清除账号、挑战、历史和去重状态。
- 旧 `challenge-v1.json` 及其备份先只读迁移；迁移输出校验完成后才切换。保留一份明确标记的旧版迁移备份，不每次启动新增。损坏文件不覆盖，失败时保留原文件并告知用户。

### 三、页面与连接管理

主 Tab：游戏进度、弹幕消息、游戏数据、挑战历史。

设置：互动规则、连接管理、快捷键、本地存储。移除设置变化记录入口和旧游戏数据入口；同步修正游戏进度中的全部记录链接。历史详情仍显示该次挑战的变化记录，进行中的必要近期反馈可保留。

连接管理采用三个独立分区，每张卡片有标题、状态和所属操作：

1. 抖音直播：当前账号摘要、房间号、直播间状态、连接/断开；账号管理复用已有个人空间，避免重复登录入口含义不同。
2. 英雄联盟：检测状态、当前玩家、采集状态、校准说明；明确校准影响当前挑战的游戏基线，不影响直播账号。
3. 高级选项：手动 Cookie、演示、诊断，默认折叠。敏感值不出现在日志与导出诊断中。

维持现有温暖、圆角、彩色点缀风格；窄窗口下分区顺序堆叠，弹层和长列表有明确滚动边界。

### 四、消息解码与诊断

- 首先按 method 判断是否支持；未知消息直接计入未支持类别，不假设其内部结构。
- 控制与房间统计消息独立解析，不读取用户字段，不要求互动消息 ID 才处理控制指令。
- 评论、点赞、关注、进场、礼物分别使用对应用户字段；保留消息 ID 字符串精度和已有礼物连击语义。
- 分离推送帧错误、已支持消息的解码失败、正常忽略/未支持类型、业务处理失败。界面说明这些数字不能直接相减推算丢失礼物数。
- 单条损坏消息不影响同批其他有效消息；ACK、游标、重连与控制结束逻辑保留并增加回归测试。
- 诊断只存有界脱敏元数据。不能仅把错误改成忽略以掩盖已支持类型的损坏消息。
- 当前只能证明上述代码缺陷；如上线后仍有错误，利用新分类诊断继续定位，不宣称已解决历史 301 次错误的全部原因。

### 五、统一组件

- 新建可复用单选组件，替换所有原生下拉菜单；沿用页面柔和紫色、圆角、细边框和轻阴影，统一悬停、选中、禁用和错误态。
- 支持上下键、Home/End、Enter/Space、Escape、Tab 离开和字符查找；具备可访问名称、展开状态、选项选中语义和焦点回归。
- 浮层使用独立挂载层并根据视口定位，避免被历史面板、设置弹窗或滚动容器裁剪；空间不足时向上展开并限制高度。
- 输入框、按钮、开关共享尺寸、圆角、颜色及焦点样式；不改变数字输入上下限与已有校验逻辑。
- 礼物选择保留图标、搜索和已选禁用，使用同一套样式状态；不把多礼物配置误改为单选。

## 模块边界

- `electron/douyin-wire.cjs`：协议分派和类型专属解码。
- `electron/douyin.cjs` 与新的有界诊断模块：接收阶段分类、错误隔离和统计。
- 独立本地存储模块：迁移、恢复日志、原子检查点、历史文件、占用和缓存清理。
- `electron/product.cjs`、`challenge-library.cjs`、`gift-catalog.cjs`、`interaction-normalizer.cjs`：接入存储，区分展示快照与持久化数据。
- `electron/main.cjs` 与预加载桥接：按需订阅、历史分页/详情、目录、存储管理；所有读取在主进程按当前登录作用域检查权限。
- `src/main.jsx`、`DataPanels.jsx` 和各页面组件：独立 Tab、按需读取、消息窗口与刷新边界。
- 共用选择组件与样式文件：全局可访问交互及表单视觉规范。

## 验证与验收

1. 先增加失败回归测试：控制状态为整数、未知类型不解析、已支持消息损坏仍报错、同批有效消息继续处理、回调异常不冒充解码失败。
2. 存储测试使用临时目录：旧版迁移、备份恢复、截断日志、写入失败、退出等待、跨账号隔离、重启重放和连击继续计数；不触碰真实用户存档。
3. 小规模有界消息测试记录写入次数、字节量、广播体积和列表挂载数量；不在用户电脑上做无限或高并发压力测试。
4. 确认无变化游戏轮询不触发整份持久化；历史及礼物目录不包含在高频广播；历史增长不会增加每条消息的历史重写成本。
5. 前端检查独立游戏数据 Tab、隐藏页停止昂贵渲染、分页详情、清理缓存说明、连接分组和所有菜单的键盘/鼠标交互。
6. 检查小窗口、模态框、列表底部菜单、长标签和空结果，避免裁剪及双滚动回归。
7. 运行现有全部单元测试、构建及 Electron 冒烟测试。真实抖音/游戏验证与离线测试结果分开汇报；未进行现场验证不得声称已验证。
