# 游戏模式与挑战验收用例

本轮仅更新源码和本地页面构建，不生成安装包。自动化覆盖的是合成快照、隔离存档与 Electron 界面；下列真实对局仍需人工验证。

## 开始前

1. 完整退出旧应用，在项目目录执行 `npm.cmd run dev`，登录后进入「设置玩法」。不要同时运行安装版和开发版。
2. 先选择模式和玩法，设置较大的目标（例如 100），保存并开始。游戏数据出现后，第一份有效快照作为基线，开始前的击杀/推塔不补算。
3. 打开挑战展示窗口。需要验证观众加码时另行连接正在直播的房间；游戏计数本身不要求连接直播间。
4. 先记录挑战当前完成数。下列「+1」均指相对此数值的增量，切勿为测试清空已有存档。

## 菜单与存档

| 操作 | 预期 |
| --- | --- |
| 选择经典 5v5 | 英雄击杀、己方推塔、大龙、小龙、峡谷先锋，共五项 |
| 选择大乱斗 | 仅英雄击杀、己方推塔，共两项 |
| 分别给两组英雄击杀设置不同目标与规则，再切换并恢复 | 各自保留，进度与规则不互相覆盖 |
| 完整退出、重启并手动恢复 | 两组存档都在，累计进度保留；恢复后的首份快照重新建立基线 |
| 查看旧存档与历史 | 未标记模式的旧数据属于经典 5v5，历史可按模式筛选 |

## 真实对局计数

| 场景 | 预期 |
| --- | --- |
| 经典、极地、海克斯中选择对应组的英雄击杀，自己击杀一名敌方英雄 | 完成数 +1；队友击杀或自己仅助攻不增加 |
| 同一快照被连续采集 | 不重复增加 |
| 各模式中选择对应组的己方推塔，摧毁一座敌方防御塔 | 完成数 +1；队友或小兵最后一击也算 |
| 只打掉镀层、己方防御塔被摧毁 | 不增加推塔完成数 |
| 经典组分别测试大龙、小龙、峡谷先锋 | 对应我方事件 +1；对方击杀不加。远古龙算小龙，召唤先锋及虚空巢虫不算先锋击杀 |
| 保持同一大乱斗挑战不暂停，上一局新增 2，下一局新增 3 | 总进度比测试开始前增加 5；极地与海克斯共用累计，不因重开对局清零 |
| 经典挑战遇到 ARAM，或大乱斗挑战遇到 CLASSIC | 明确提示当前模式不匹配，原进度保留，不把另一模式的进度补入 |
| 手动暂停期间击杀，然后恢复 | 不补算暂停期间；恢复后的有效新增继续计算 |

跨局验收必须保持挑战运行；重启、手动暂停、切换模式恢复都会重新取基线。长时间断线或可确认的同局分数回退可能安全暂停，需要检查提示并手动核对。

## 展示与排版

- 标题旁显示对局模式，未进入游戏时显示等待；更换艾欧尼亚等配图不会更改模式或统计。
- 目前真实 `ARAM` 显示「大乱斗（子类型待确认）」。自动区分极地与海克斯尚待本机客户端读取授权；不能将模拟验收中的具体标签当作实战已接通。
- 游戏进度与观众加码各占一行，显示最近一次变化原因及其 `HH:mm`；时间保持不变直到下次变化，没有变化记录显示 `--:--`。
- 使用长昵称、长礼物名及窄展示窗口：文字省略、时间完整；赠礼图标仍使用已选真实礼物图，不被主题着色替代。
- 主界面分别切亮色、暗色，检查 960 × 700 及较大窗口下模式标签、卡片、滚动；挑战展示主题不跟随主界面变化。

## 如有漏计

保留「游戏数据」快照以及当时模式、选择的玩法、事件发生时间、挑战是否运行。推塔重点保留 `gameData`、`activePlayer`、相关 `allPlayers` 和 `events.Events` 的 `TurretKilled` 条目；不要附带登录 Cookie。无法识别的塔命名不会猜测计数，需根据真实样本补适配。
