# 玩播 · PlayCast

本文保留完整功能说明。开发和发布命令以 [开发指南](development.md) 为准；运行源码现已迁移为严格 TypeScript，Electron `.cjs` 是由 `.cts` 重新生成的产物。

Electron + React + UnoCSS + Vite 的本机直播互动工作台。首版只支持抖音，同时运行一个玩法；无需运行 dycast、DouyinLiveWebFetcher 或转发服务。

产品名称不绑定具体直播平台、游戏或玩法，后续扩展仍沿用「玩播 · PlayCast」。名称尚未进行商标或重名核查。`package.json` 的内部名称及原数据目录保留 `live-interaction-tool`，不会因对外改名迁移或清空账号、挑战存档。

## 系统托盘与退出

点击主窗口的关闭按钮会隐藏到 Windows 系统托盘，直播连接、游戏采集和已打开的弹幕／挑战弹窗继续工作。点击托盘中的 PlayCast 图标可恢复并聚焦主页面；如果图标被 Windows 收起，可在任务栏右下角的隐藏图标区域找到。

右键图标可选择「打开主页面」「弹幕弹窗」「挑战弹窗」或「退出」。弹窗入口仅在对应登录、直播间或玩法条件满足时可用，重复打开会恢复已有窗口。只有「退出」会关闭整个应用；有未保存的编辑时仍需确认，取消退出或保存失败时应用保持运行。若系统托盘初始化失败，关闭主窗口会按原有退出流程处理。

## 启动与验证

需要 Node.js 22 或更新版本。

~~~powershell
npm.cmd ci
npm.cmd run dev
~~~

开发服务固定为 http://127.0.0.1:5188，端口被占用时明确失败。更改 Electron 主进程后需要完全退出并重启；页面更新支持热刷新。

~~~powershell
npm.cmd test
npm.cmd run build
npm.cmd run smoke
npm.cmd start
~~~

`start` 加载本机构建产物。Windows 安装包构建与验收见下一节。

## Windows 安装测试版

在 Windows x64、Node.js 22 或更新版本上执行：

~~~powershell
npm.cmd ci
npm.cmd run dist:win
~~~

输出 `release/PlayCast-Setup-0.2.0-x64.exe`（版本号随 package.json 更新）。双击后选择安装目录，通过桌面或开始菜单的「玩播 · PlayCast」启动；安装后不需要 Node.js、源码或开发服务。默认按当前 Windows 用户安装，无需管理员权限，正式程序名为 `PlayCast.exe`。安装器及主程序均嵌入项目 ICO。当前测试版没有代码签名，Windows 可能显示「未知发布者」；没有自动更新，也不会自动上传安装包。

请先退出开发版再启动安装版。两者默认共用 `%APPDATA%/live-interaction-tool` 下的账号、设置和挑战记录，以免改名后看不到旧数据；同一目录使用单实例锁。卸载默认保留用户数据，彻底清理请先在应用内明确执行「恢复初始状态」。卸载不是注销账号。

打包白名单只包含 `electron`、`dist`、产品名称配置、运行所需依赖；不包含用户资料、Cookie、测试脚本、设计母图或参考项目。开发、测试参数在安装版中不启用；默认始终加载随包页面，不依赖 `127.0.0.1:5188`。

`npm.cmd run pack:win` 仅生成 `release/win-unpacked` 目录，可直接运行其中的 EXE，但必须保留整个目录；不要单独拷出 `PlayCast.exe`。`npm.cmd run verify:package` 对这份真实 EXE 做隔离验收，覆盖首次引导、两种展示、即时设置、资源加载、退出及重启保存。可传入其他安装位置：`npm.cmd run verify:package -- "C:/安装目录/PlayCast.exe"`。测试使用 Chromium 标准 `--user-data-dir` 指定独立绝对目录，不接触默认用户资料，也不会连接真实直播间。不要手动让两个实例同时共用一份存档。

构建依赖、Electron 与 NSIS 在首次构建时需要下载。真实扫码登录、直播消息/礼物、LoL 对局及直播伴侣采集仍需使用你的真实账号与游戏环境验收；打包本身不代表这些外部链路已验证。

### 随包静态资源

界面使用系统字体（Segoe UI、Microsoft YaHei 及 sans-serif 回退），不加载自定义字体或覆盖字体行度量。现有静态图片位于 `public/assets`，构建时复制到 `dist/assets`；后续制作 exe 安装包须包含完整 `dist` 目录。账号头像及官方礼物图标属于平台动态内容，仍由网络加载。

应用图标位于 `public/assets/brand/playcast.png` / `playcast.ico`。ICO 包含 16、20、24、32、40、48、64、128、256 像素版本，主窗口、展示窗口、配置窗口和登录窗口统一使用。改名与图标入口为 `app-brand.json`、`electron/branding.cts`；修改原生窗口图标后需重启应用。`electron-builder.cjs` 为安装器及正式 `PlayCast.exe` 嵌入同一 ICO，不修改开发依赖中的原始 `electron.exe`。

挑战和弹幕窗口仍属于同一应用，通过各自窗口标题区分；独立 EXE 拆分已按用户要求暂缓。弹窗图标采用独立的深色背景语义色，在线浅金、评论薄荷绿、点赞柔粉、进场浅蓝、关注杏橙、礼物淡紫；真实礼物图片不着色，虚拟列表行高及锁定解锁热区不变。

### 展示窗口显示

挑战和弹幕展示保留置顶、拖动、锁定鼠标穿透及独立外观设置。已移除贴边吸附、自动隐藏和展开把手，避免直播采集录入收起／展开过程；旧版保存的自动隐藏设置会被忽略。

Windows 跨虚拟桌面显示暂未自动实现（Electron 的 `setVisibleOnAllWorkspaces` 在 Windows 无效）。可先用 `Win + Tab`，右键对应展示窗口，选择「在所有桌面上显示此窗口」；不要选择固定整个应用。后续程序内自动固定需要单独做 Windows 原生兼容性验证。

### 主窗口主题

「工作台设置 → 外观」提供亮色、暗色和随系统。首次使用默认随系统；选择即时生效，并独立于登录账号保存在用户数据目录的 `appearance.json`（仅版本和主题选项，不保存切换历史）。下次启动在页面绘制前恢复；随系统会响应 Windows 外观变化，手动亮／暗不受系统切换影响。

原界面是亮色主题，暗色采用炭灰底和柔和彩色语义。仅主窗口的引导、工作台、个人空间及内部设置参与切换；挑战展示、弹幕展示和它们的独立配置窗口不变。普通清理可重建缓存保留主题，完整「恢复初始状态」删除主题偏好并恢复随系统。

## 用户动线

选择抖音 → 打开官方窗口扫码登录并验证 → 进入工作台。引导仅有选择平台、登录账号两步。

进入后即可选择单玩法并保存规则、开始累计游戏进度。需要观众互动时，从右上角直播连接状态，或「弹幕消息」空状态中的「连接直播间」打开同一个连接面板；不要求先连接房间，也不会因连接失败退回引导。

- 扫码使用抖音官方页面，不自行生成二维码。登录窗口独立于采集初始化，不会因为采集成功而关闭。
- Cookie 变化后自动验证公开账号资料。Cookie 存在、账号验证成功、实际收到礼物是三个不同状态。
- 顶栏个人空间显示头像、昵称、账号、签名、粉丝/关注数，支持刷新与二次确认退出。缺失字段显示“未提供”。
- 返回应用时验证加密存档中的登录；未结束挑战暂停恢复。退出只清理本工具账号，保留挑战进度，不影响其他浏览器。
- 更换模式组、玩法、平台或账号会暂停并保存旧挑战。新挑战按平台 → 账号 → 模式组 → 玩法保存，连接、断开或更换直播间不重置或暂停游戏进度。开始挑战不会自动连接房间；只有当前已连接房间的实时互动计入当前账号的挑战。
- 旧版房间草稿按原 ID 保留；同一玩法若有多份旧草稿，会分别显示并允许选择，恢复时保留进度、规则与点赞余额。已结算历史不改写。
- 旧人头存档保留进度并暂停；可明确选择继续旧进度。旧评论奖励关闭、旧名称礼物规则需重新选择稳定 ID，不自动猜映射。

## 玩法与规则

先选择「经典 5v5」或「大乱斗」，再选择玩法。经典 5v5 提供以下五种玩法；大乱斗仅提供英雄击杀与己方推塔，极地和海克斯共用这一组挑战。两组的挑战进度、规则预设和存档各自独立，历史带模式标签并可筛选；旧版未标记模式的存档归入经典 5v5，不清零、不复制到大乱斗。

| 玩法 | 自动完成数口径 |
| --- | --- |
| 英雄击杀 | 当前玩家的英雄击杀 |
| 己方推塔 | TurretKilled 中被摧毁的敌方防御塔；包含队友、小兵最后一击，不含镀层 |
| 大龙击杀 | 我方队伍 BaronKill |
| 小龙击杀 | 我方队伍 DragonKill，包含远古龙 |
| 峡谷先锋击杀 | 我方队伍 HeraldKill，不含召唤先锋或虚空巢虫 |

事件名与分数字段已核对 Riot 官方文档/样例。无法确认击杀者所属队伍时不自动计数并提示校正。没有发生过目标事件不等于不支持；尚无对局时显示等待。以 Live Client 的 `gameData.gameMode` 判定模式组：`CLASSIC` 为经典 5v5、`ARAM` 为大乱斗，不再要求 `Map11`；其他模式或与所选挑战不符的模式不自动累计，也不在回到支持模式后补算这段进度。可在对局开始前配置玩法。

Live Client 的 `ARAM` 本身不能可靠区分极地和海克斯。当前未接入客户端认证信息读取，因此真实对局统一显示「大乱斗（子类型待确认）」，不根据地图名或装饰主题猜测；两种大乱斗的英雄击杀与推塔仍按 ARAM 计数。代码已支持校验后的队列元数据（450 / 720 / 100 为极地，2400 为海克斯），目前仅以合成数据验证该分支。本机客户端会话读取需获得明确授权后另行接入，不能视为已实现自动子类型识别。

推塔按被摧毁防御塔的阵营判断，兼容旧版 `Turret_T1_…` / `Turret_T2_…` 与实战快照中的 `Turret_TOrder_…` / `Turret_TChaos_…` 命名；不依赖最后一击玩家姓名。只计敌方塔，重复事件不重复加数。升级不会自动恢复已暂停的挑战或回填漏计进度；确认后继续挑战，漏计部分可手动校正。

补刀因接口按十位取整已移除；升级时删除旧补刀挑战、草稿、历史及规则预设，不转换成推塔进度。游戏数据页仍可查看接口的原始补刀值。

同一挑战跨对局累计：上一局 5 + 新一局 3 = 总进度 8。识别到同一玩家的新对局后，即使排队超过两分钟仍继续；重复快照不重复加数。同局长时间断线仍暂停等待核对。手动暂停、重启后的恢复只从新起点累计，不补算停用期间；其他已结算挑战不会混入。

实战测试步骤见 [游戏模式与挑战验收用例](game-mode-acceptance.md)。自动界面验收：先运行 `npm.cmd run build`，设置 `$env:LIT_SMOKE_CASE='game-modes'` 后运行 `npm.cmd run smoke`；使用隔离账号、临时存档和合成游戏数据，不连接真实游戏或直播间，也不构建安装包。

运行模式“通用”页签及模拟互动仅在本地开发运行（`npm run dev`）显示并启用，生产包不提供模拟模式，直接调用入口也会拒绝。

观众互动增加目标数，游戏进度增加完成数：

- 点赞：每 N 个赞 +1，可关闭。更改点赞阈值/开关重新积攒余额。
- 关注：每个新增关注 +M，同一挑战同一用户只奖励一次。
- 礼物：多行选择礼物 → 每个 +M，按平台 ID 和礼物 ID 匹配；不再按名称猜匹配。
- 评论词：开启后每行填写一个词，评论包含任意词则目标 +1。每条最多 +1，同一观众再次发送仍计数，重复推送不重复计数。最多 20 个词、每词 80 字，英文区分大小写。
- 达到目标不会自动结束；点击「完成挑战」并确认才结算。未达标可选择「提前结束」。

## 玩法存档与挑战历史

- 「保存并切换玩法」保留原挑战的目标、完成数、互动规则、点赞余额与手动校正。选回对应玩法，点击「恢复这个挑战」，核对后再继续。
- 同一范围内每种玩法保留一份未结束的挑战，同一时间只运行一个。退出登录、关闭程序不会结算或清零；重开后恢复为暂停，游戏离线期间不补算。
- 「挑战历史」保存当前平台账号下各直播间的已结算记录，支持按玩法、结果筛选。展开可查看时间、最终目标与进度、各类互动贡献、结算时规则、校正值与最多最近 300 条变化记录。新挑战不会覆盖历史。
- 老存档升级保留原有进度。旧数据没有的贡献明细和时间显示为不完整／未记录，不推算历史数值。
- 正式数据保存在 Electron 用户数据目录的 `challenge-v1.json`（内部已升级为多玩法格式），每次有效变化立即写入，使用临时文件替换及 `.bak` 备份。读取损坏时尝试备份恢复；损坏原件另存 `.corrupt-时间戳`，无法恢复则保留原件并明确提示。保存失败时不要直接关闭程序。
- 本机存档不是云同步或防断电保证；演示模式的挑战及历史不写入正式存档。

累计连击 1 → 2 → 3 → 结束 3 产生增量 1、1、1、0；每个奖励 5，总共 +15。同用户新一轮赠送继续计数。只有重复通知被过滤，不是把多次赠送去掉。暂停时保持去重/高水位，恢复不补算暂停期间礼物。重连及重启保存高水位；断网期间不保证补回消息。

## 直播展示屏

工作台只有「当前挑战」「弹幕消息」「游戏数据」三个主页面。「挑战历史」在当前挑战页的次级标签中；结算后会自动打开历史。当前挑战页管理挑战展示窗口和互动规则，弹幕消息页管理弹幕展示窗口和直播间连接，游戏数据页管理游戏连接。游戏数据没有独立展示窗口。工作台设置分为「通用」「快捷键」「本地存储」，不再设高级诊断。

「通用 → 调试模式」关闭为正式模式，开启为演练模式，切换前需确认。进入演练会保存并暂停正式挑战、断开真实采集；演练进度和消息与正式数据隔离。退出演练不自动恢复挑战或重新连接。调试模式只在本次运行有效，重启默认正式模式。查看真实接收诊断不需要开启调试。

手动 Cookie 导入迁至「个人空间 → 其他登录方式」，未登录引导也提供同一备用入口。仅支持该登录方式的平台显示此入口。输入不回显已保存凭据，提交即清空输入并自动验证账号；退出登录是清除凭据的统一入口。

所属页面仅保留「打开展示窗口」，已打开时点击会唤回原窗口。当前挑战与挑战历史共用标题右侧的展示入口，引导页不显示。登录验证成功即可进入工作台，查看历史、配置挑战和查看游戏数据；连接房间是独立操作，不再作为引导步骤。同账号连接过程中保持当前页面、连接面板及未保存的玩法输入；账号或来源失效仍立即隐藏私有内容。登录卡片和手动凭据区域使用同一内容列。设置、锁定和关闭均在展示窗口内操作，不再提供重复的「更多」配置入口。挑战窗口不依赖房间连接；消息窗口需先登录并确认房间，无需先开始挑战，未确认时入口给出提示。

连接状态区分准备中、连接中、重连中、连接失败，以及「未开播 / 已结束」。初始化前使用同会话、有超时及大小上限的房间页面检查；明确未开播时直接完成准备，不等待页面播放器或弹幕连接。仅当前房间明确的离线元数据或结束推送才显示未开播提醒；无消息、页面验证码或未知状态不当作未开播。首页和弹幕页会提示未开播时暂时收不到互动消息，开播后需重新连接。同值 Cookie 重写和同凭据资料刷新不清空当前身份或连接；真实凭据变化仍重新验证，仅为同账号、同房间恢复既有连接意图，主动断开、退出或切换来源后不自动连接。

- 召唤师峡谷（默认）、艾欧尼亚、德玛西亚、皮尔特沃夫四套地区主题，使用随包风景与庆祝徽章（非官方游戏界面，新增资源合计约 236 KiB）。可自定义 60 字以内的挑战名称，留空跟随玩法。
- 独立窗口从上到下显示标题、准确的当前进度 / 目标、进度条和已启用的互动规则。礼物使用已选目录条目的真实图标；图片不可用时显示中性占位，名称仍保留。
- 挑战窗口默认 320 × 440，最小 300 × 420；消息窗口默认 320 × 480，最小 300 × 360。两者均为 4px 微圆角、无外框与外阴影；尺寸指画面内容，不含系统标题栏。旧挑战默认 420 × 280 和 280 × 380 会迁移为新版竖版；自定义尺寸按最小范围保留，可在配置页填写宽高。规则每页最多 4 条，每 8 秒轮播；礼物长名称最多显示两行，完整规则在主窗口查看。评论命中多个词仍只增加一次目标。
- 固定两行展示最近的目标／进度变化原因：累计点赞达标、关注、评论关键词、赠礼增量、游戏计数、手动调整和临时补记。文字保持单行、超长省略，右侧完整显示该次变化的本地时间 `HH:mm`，无记录时为 `--:--`；不是持续走动的时钟。顶部展示实际对局模式，地区配图与主题选择不变。追平已暂记的进度只显示确认，不再冒充加数；队伍目标仅说明我方队伍指标，不猜测具体击杀者。

- 每个挑战首次确认达标会在底部规则区播放约 3.2 秒的静音庆祝，上方标题、统计及变化原因保持原位。地区徽章搭配五种玩法的高光星星、丰收金币、大龙彩带、小龙火花、先锋方块效果。庆祝时暂停规则翻页，结束后恢复；遵循系统减少动态效果设置，也可手动关闭动画。
- 临时补记未确认、零目标不会触发；重开窗口、恢复存档、校正后再次达到目标都不重复播放。动画期间目标增加会终止本次庆祝。达标不会自动结算或清空挑战。
- 「预览庆祝」仅测试画面，不修改计数、挑战存档或历史。退出登录后独立窗口隐藏挑战与规则。展示偏好保存在本机，装饰图片随构建打包；真实平台礼物图片仍需要网络。

新版即时配置页使用 `live-settings`（原 `separate-settings` 命令是别名）验收；引导、重登和历史布局使用 `live-layout`。两者都使用隔离账号与合成消息，不接触真实直播间。

## 礼物目录

本项目直接请求已核验的抖音官方 /webcast/gift/list/ 接口，使用同一隔离账号会话。2026-09-28 实际无登录探测返回 1,287 个条目，全部带 HTTPS 官方图标；数量会变化，不是固定“全部礼物”承诺。

选择器提供搜索、图标、名称、价格和多条奖励规则。界面区分官方返回目录、缓存、已收到礼物子集；目录失败可以重试，不删除已配规则。账号/房间/平台隔离缓存。图标失败使用中性占位，不用生成图片冒充官方礼物。目录返回不意味着每个礼物对每个账号/房间都可赠送。

礼物目录最多保存 8 个范围、合计 16 MiB 序列化数据，最近使用的范围优先保留；图标仅接受长度受限的安全 HTTPS 地址。主窗口和两个展示窗口共用独立、非持久化且关闭 HTTP 缓存的 UI 会话，与账号认证会话分离。「清理可重建缓存」不会删除凭据、认证 Cookie、设置、挑战草稿或历史；挑战历史长期保留，只有明确手动删除才移除记录。

「工作台设置 → 存储 → 恢复初始状态」可删除本机全部应用用户数据。必须输入「重置」确认；包含所有账号的挑战、草稿、互动规则、历史、登录凭据、直播间、展示偏好、缓存、诊断及旧存档／恢复备份。操作不可撤销，会关闭登录、展示及配置窗口，回到首次使用的平台选择。程序与随包静态素材、系统浏览器不受影响。清理失败时暂时停用其他功能，可重试；若中断，下次启动先继续清理，不加载旧存档。请勿将此功能当作缓存清理。它是逻辑删除，不承诺磁盘取证级擦除。

重置隔离验收：构建后设置 `$env:LIT_SMOKE_CASE='reset'`，运行 `npm.cmd run smoke`。中断恢复验收使用 `node_modules\.bin\electron.cmd tests/reset-recovery-smoke.cjs --smoke`；设置 `$env:LIT_RESET_FAIL_ONCE='1'` 可额外验证启动清理失败后重试。这些场景只操作临时测试资料，不清除实际用户的数据。

## 计数与手动校正

- 开始或恢复时下一份有效游戏数据作为基线；接入前/暂停期间进度不补算。
- 跨局保留挑战累计；新局建立新基线，不重复计旧事件。
- Ctrl+Alt+↑：临时补记当前玩法 +1，真实后续增量追平时不重复增加。
- Ctrl+Alt+↓：撤销未追平补记。
- Ctrl+Alt+→ / ←：目标 +1 / -1。
- Ctrl+Alt+K：唤起完成数修正。快捷键冲突在设置里展示。
- 超过两分钟游戏数据空档、身份或分数异常回退会暂停，要求核对。
- 独立展示窗口用于直播软件窗口捕获；弹幕页与玩法是否暂停无关，每类最多 200 条／1 MiB，合计最多 1,000 条／5 MiB。
- 演练数据与正式挑战相互隔离，不把模拟账号或模拟事件说成真实连接。

## 安全与扩展

凭据仅在 Electron 主进程处理，运行时使用非持久化会话，跨重启用系统 safeStorage 加密；拒绝明文降级，不写入挑战 JSON、页面快照或日志。高级手动 Cookie 导入仅供排障，不是正常动线的必要步骤。

账号资料沿用本地实现的 dycast fetchMeInfo 请求链（msToken / a_bogus / SM3），不依赖参考项目进程或文件。采集通过官方网页初始化签名，再由本项目独立维护 WebSocket、ACK、心跳、重试及 Protobuf 解析；登录或风控验证需用户自行处理，不绕过。

平台适配器分别负责认证、房间解析、采集、消息语义和礼物目录。挑战消费带平台/账号/房间范围的统一增量消息，新增平台不需改玩法算法。测试中提供第二个隔离平台验证缺失能力降级，不作为产品真实平台展示。

LoL 数据只读固定回环 HTTPS 127.0.0.1:2999/liveclientdata/allgamedata。仅该请求接受本地自签名证书，不关闭全局 TLS。连接成功时目标周期为 1000 ms，等待对局或请求失败时为 3000 ms；周期包含本次请求耗时，串行执行，慢请求不会叠加。采集详情显示当前采用的周期与请求耗时；这些数值不等于游戏事件的端到端延迟。抖音实时推送不受此轮询周期影响。渲染进程保持隔离、沙箱且禁止 Node 集成。

## 验证边界

### 扩展弹幕与房间动态

「弹幕消息」分为「实时消息」「房间动态」「接收诊断」。扩展消息在房间动态查看；受限结构采样收纳在其折叠的「解析详情与结构采样」中。协议和礼物计数、待适配消息类型及安全异常信息统一在接收诊断查看，不再放入工作台设置。仅当前可见子页发起查询，同时最多一个请求，离页或窗口隐藏后暂停，过期响应不会写回；不增加持久化消息缓存。演练模式不展示真实房间动态或诊断。更新主进程后请完整重启应用、重新连接直播间；旧版只统计过类型名的消息无法补回内容。

- 已知字段：房间消息、房间统计、粉丝团、表情弹幕、房间通知、小时榜入口、房间排行榜。房间排行榜只展示本包前 4 项，隐藏身份保持匿名，条目顺序不推断为真实名次。
- 部分解析：房间横幅、商品动态、电商通知、房间数据同步、通知特效、福袋活动、屏幕弹幕、热聊消息、热门房间消息（HotRoom）。不会执行网页模板或特效；商品 ID 协议冲突、电商/同步内部数据等仍待确认。热聊最多展示 4 项热门内容，不当作普通评论触发奖励。HotRoom 仅按参考协议读取公共信息及 BitMap 原值，字段业务含义待真实消息确认，不解释为热度增量、在线人数或点赞。
- 待确认：评论点赞、福袋临时状态、福袋奖励、福袋结束、房间指示消息（RoomIndicator）、抽奖新消息（LotteryEventNew）。仅识别类型／可确认的公共信息，不推断实际点赞量或中奖结果；RoomIndicator 与 LotteryEventNew 连公共信息布局也未确认，仅支持结构采样。
- 扩展消息不经过互动归一化、普通弹幕统计或挑战奖励，包括表情与屏幕弹幕暂不触发评论词。房间统计字段不是当前在线人数。
- 语音弹幕（AudioChat）部分解析：用户、文字及音频时长原值；不猜测时长单位或文字是否为转写，不展示、下载或播放音频链接，不触发评论词。横幅刷新（InRoomBannerRefresh）、评论话题（RoomCommentTopic）、特权屏幕弹幕（PrivilegeScreenChat）暂无可靠字段定义，仅识别类型并支持受限结构采样，不套用名称相近类型的字段。
- 抽奖结果事件（LotteryDrawResultEvent）暂无可靠字段定义，仅按类型名识别并支持受限结构采样；不推断中奖人、奖品、数量或金额，不视为收到礼物或挑战奖励。
- 直播流适配（RoomStreamAdaptation）展示协议适配类型及高度、主体中心、内容顶部／底部比例原值；不自动应用画面配置，不参与挑战计数。比例仅从合法的有限 fixed32 浮点字段读取。DataLifeLive 暂无可靠定义，仅识别类型并支持受限结构采样，不猜测业务用途或公共信息结构。
- 每种类型合并为一条最新记录及收到次数，当前最多 29 条；每条最多 24 个展示字段、文字最多 500 字符，单消息解码上限 64 KiB。查看面板按 2 秒刷新，关闭后停止查询。重连清理记录，账号切换／验证失效清理扩展数据。
